# Python 可视化双端同步编辑器目录与技术分层计划

## 问题与目标

本项目优先设计一个 Avalonia/.NET 桌面编辑器，使 Python 源码与 Scratch 风格积木在可表达子集内双向同步。智能体工作台暂时搁置，不纳入本轮源码目录和实现步骤，仅保留未来接入应用宿主的扩展位置。

本计划记录当前实现状态、目标架构和后续实现顺序。状态以当前工作区源码为准；尚未在源码中落地的目录、接口和流程均视为待实现。

- 项目级变量/列表管理：`project.json` 保存初始值；“管理变量…”对话框支持新增、重命名、删除和引用检查；变量/列表重命名会改写磁盘及未保存编辑器中的字面量引用，存在引用时阻止删除。
- 运行时数据 API：`get_variable`、`set_variable`、`add_to_variable`（旧 `change_variable` 保留兼容）、列表操作和 `list_values` 快照。
- 旋转矩形碰撞：按当前造型图片尺寸、`size` 和 `direction` 计算；`touching` 使用分离轴检测，`touching_pointer` 使用旋转矩形内点判断，`touching_edge` 使用旋转后边界；调试碰撞箱独立置顶并与图片共用舞台几何字段。

- 单个 Scratch 风格积木原型：`ScratchBlockControl` 自定义绘制运动积木轮廓、蓝色填充和参数槽；移动/旋转积木已使用该控件。

### 已实现：受管理导入与 v3 模板

- “更多 → 添加 → 导入脚本…”和“管理导入…”打开主窗口内浮层，支持添加、别名修改、移除、取消和确认；应用后可撤销重做，不立即写盘。
- 普通用户脚本及 v3 角色/背景显示只读导入摘要，实际语句位于完整文件模块级位置。普通脚本保留模块文档字符串和 future 导入位置；原有手写导入继续可编辑。
- 项目导入按清单稳定 ID、类型及实际模块路径校验，拒绝角色、背景、自身、重复及名称冲突。标准库目录来自实际 Python 环境，不安装包，不执行用户模块。
- 角色/背景手写 import/from-import 显示导入规则错误，可将当前独立单行导入转为受管理导入；语法未完成时不猜测手写规则。新建对象使用 v3；已确认 v1/v2 提供预览升级，不自动迁移。

### 已实现：Python 环境、项目运行与终端

- 设置新增“通用 → Python 可执行文件”，支持浏览、自动检测、验证并应用；显示解释器版本与实际路径，保存到用户级设置。运行期间禁止更换，空闲更换时取消旧分析、验证新 Helper 并刷新诊断；构建用 Python 配置独立。
- 运行针对当前项目而非当前打开脚本。保存失败、磁盘冲突、对象结构、语法或导入规则错误阻止启动；固定运行源码快照，后续编辑在下次运行生效。
- 静态分析 Helper 与用户执行进程分离。产品 `Python.Runtime` 提供 API 1 与旧模板导入兼容层，不覆盖项目已有基类；分析环境加入兼容接口路径。
- 系统入口 `scripts/main.py` 已接入受管理模板 v1，不供用户编辑；新建项目直接生成，已有项目在运行准备时仅升级原始空模板（兼容 LF/CRLF）。入口被外部修改或版本未知时阻止运行且保留原文件，准备结束前再次复检磁盘源码。入口不应用用户导入规则，也不进入用户错误导航快照。
- 生命周期由系统入口调用产品运行时：构造所有对象、注入上下文、检查启动/消息/点击处理器、初始化全部实例、开放消息路由、顺序执行启动处理器，再进入主线程持续事件循环；初始化失败不进入启动阶段。入口桥接限定当前执行线程、每会话一次，异常时也清理会话。普通用户脚本不会自动执行。角色点击及同步消息广播已接入；尚无其他舞台事件、专用动画或并行事件执行。
- 舞台区选择器切换终端／舞台。终端输出只读且可复制、清空；运行握手完成后启用底部输入并支持 `input()`；结束或停止后保留输出并禁用输入。切换视图不影响会话。
- 终端批量刷新并限制输出缓存；异常通过 v2 结构化协议传回，默认错误卡片显示运行快照对应的用户行列、区域名称及代码片段，系统包装与原始绝对路径收于可展开的诊断详情。支持异常链、异常组与工作线程异常，用户主动输出的 stderr/traceback 不改写。运行前语法与导入诊断复用用户视图映射。编辑、重命名、删除、切换或重新打开项目后拒绝旧结果导航；点击前后复检源码，显示和导航使用同一运行快照。
- 停止、关闭项目、切换项目与退出会回收执行进程；等待输入与循环支持停止，超时终止进程树。进程隔离不等于安全沙箱。协议及兼容边界见 `src/VisualizedAgentCoding.Python.Runtime/README.md`。

#### 系统入口验收

- 新建临时项目，确认磁盘入口带 `vac:entry-version=1`，界面仍不提供入口编辑。添加两个角色的初始化及启动输出，运行应先输出全部初始化，再按对象顺序输出启动内容。
- 将临时项目入口恢复为原始空 `main()` 模板，运行后应升级并正常执行；改为自定义内容或未知版本时，应阻止执行且不覆盖文件。
- 在用户区域验证 `input()`、异常定位、停止和重新运行；入口及运行时包装不应变成可导航的用户位置。普通用户模块须通过对象用户代码调用。
- 自动化用例位于 `ManagedProjectEntryTests`，并回归 `PythonRuntimeTests` 与 `RuntimeErrorPresentationTests`。只使用临时项目，不修改 `tests/ProjectFunctionTest`、`tests/PythonRuntimeTest`。
- 消息区域管理、公开 `broadcast` API 与系统入口建立的统一同步路由已接入；启动结束后进入持续事件循环，支持角色点击，其余舞台事件为后续功能。

### 已实现：消息区域与同步广播

- v3 角色/背景通过“更多 → 添加 → 消息事件…”新增区域，通过“更多 → 管理消息事件 → 消息名称”改名或删除。标题只读，正文可编辑；添加后选中占位行，删除前显示正文确认，操作与普通输入共用撤销重做，保存后可重开恢复。旧对象先显式升级到 v3。
- 复用 `kind=event` 与 `eventName=message:<名称>` 元数据；区域 ID 与隐藏方法不依赖消息名称。名称区分大小写，最多 248 个 UTF-16 单元，不允许空值、控制字符或首尾空白，同一对象不允许同名消息。改名保持区域 ID，不自动改写发送方。
- 在导入管理中选择“产品运行时 API → 消息广播 broadcast”，应用后在启动或消息区域调用 `broadcast("开始")`。普通用户模块也可导入并调用，但需要由对象代码触发，不会自动执行。main.py 始终由系统管理，用户无需修改。
- 请求进入系统入口建立的会话路由，同步按项目对象顺序调用全部匹配的角色和背景，全部返回后发送方继续；无接收方正常返回。嵌套消息先完成再继续外层，最多 32 层；初始化完成前和非主线程发送会明确报错。
- 运行前从验证的源码快照收集消息绑定，取代 v2/v3 对象的旧清单广播绑定，删除区域不会留下幽灵处理器。接收方异常中止运行，错误卡片显示消息区域及用户行列；等待输入、无限循环的停止回收沿用当前执行进程机制。运行结束清理消息路由，消息区域本身不维持会话。
- 不提供载荷、定向接收、异步广播和外部消息入口。点击及消息处理器在主线程顺序执行；消息 API 不是 Python 安全沙箱。

验收：临时项目创建角色 A、B 与背景；A 的启动区域发送“开始”，B 和背景接收并输出；再验证嵌套、无接收方、改名、删除/撤销/重开、消息体异常定位、输入与停止重启。自动化为 `MessageEventsTests` 和 Helper 的 `test_imports`，不修改两个保留的手动项目。

### 已实现：静态舞台与初始布局

- 舞台固定 480×360，中心原点、X 向右、Y 向上；角色以图片中心定位，窗口变化只等比缩放，舞台外内容裁切。方向 90 为图片原始方向。
- 在“资源管理器 → 对象管理器”选择角色/背景，通过“导入图片…”导入 PNG/JPEG/BMP/WebP。同一份已校验字节快照复制到 assets/images，限制 20 MB、单边 8192 和总计 1600 万像素。每次选图重置大小为 100；超过舞台边界时按 min(1,480/宽,360/高) 等比适配，并把适配尺寸定义为 100%，小图不放大。新背景居中完整显示，不裁切。旧布局缺少 normalizeImage 标记时保留原几何，显式换图才使用新规则。
- 角色支持选择、左键拖动、X/Y、大小、方向、显示/隐藏和图层编辑。隐藏角色不绘制；点击拦截只由 `click_enabled`（默认 true）决定，与可见性无关，隐藏角色若 `click_enabled` 为 true 仍会拦截点击；图层数值越大越靠前。当前背景按对象 ID 保存，不因打开其他脚本或取消选择跳回首项。
- scenes/stage.json（版本 1）按稳定对象 ID 保存图片相对路径、角色变换及当前背景。旧项目缺少文件采用默认值。没有打开脚本也能保存布局；导航/关闭/退出复用保存流程。图片随项目移动，原图删除后仍可使用；缺图保留引用并显示提示。
- 保存前复检舞台文件，外部修改时拒绝覆盖并保留本地布局；“重新加载舞台”使用与项目管理一致的窗口内浮层，取消/关闭/Esc 保留布局，确认后读取磁盘，无效文件不清空当前布局。脚本/舞台保存不是跨文件原子事务。
- 换图及保存时清理无引用的应用管理 GUID 图片。当前布局、已保存布局、项目 Python/JSON 中的明确引用及未保存编辑器文本都参与保留，共享图和手动命名文件不删除；旧已保存图片在新布局成功保存后才删除，中间未保存图片可提前清理。运行期间推迟清理，检查或删除失败时保留/提示重试。assets/objects 当前无读写用途，为未来对象资源包等功能预留，不需要手动放入图片。
- 新建和补全项目目录不再生成空 runtime/；旧目录和基类文件不删除、不覆盖。产品角色/背景基类已提供 x/y/size/direction/visible/layer，背景可调用 self.activate() 切换。每次运行合并优先级为：系统默认值 < 保存布局 < 显式初始参数 < 初始化区域赋值；明确的 0、False 不视为缺省。运行中的变换经控制通道按帧同步为独立预览，属性面板同步显示实时参数，保存不写回初始布局；结束/停止保留最后预览，下次运行重新创建对象。运行期间可以切换对象查看参数，但不能编辑属性或拖动；停止后可直接修改属性，首次明确修改退出预览，仅更新该属性，不把其他运行结果写入初始布局。也可点击“返回初始布局”恢复舞台、初始背景及参数，不读取磁盘或丢弃未保存的初始布局。已实现角色点击、背景（舞台）点击、背景切换事件、按键事件、计时器事件、瞬时移动与指针 API、非阻塞 glide_to/glide_by 位移动画、rotate_to/rotate_by 旋转动画、glide_size_to/glide_size_by 缩放动画、动画完成广播、可重入 wait、角色造型列表与 `switch_costume` 及持续事件循环。wait 仅允许启动区和事件处理器，类定义和 initialize 中禁止。角色通过只读 `self.costume` 读取当前造型名；造型管理使用属性面板浮窗；打开项目时自动清理未引用的应用管理图片。角色坐标允许超出舞台并在 480×360 边界裁剪，运行时坐标上限为 ±100000。运行开始时启动全局单调计时器，用户可通过 `from vac_runtime import timer` 或 `self.timer` 读取秒数；`timer:<秒>` 在到达阈值时执行一次，`timer:every:<秒>` 按间隔重复执行。背景切换事件使用稳定的目标背景 objectId，所有角色和背景都可监听；`activate()` 与公开的 `switch_backdrop(名称)` 共用同一运行时切换路径。删除背景时若其他脚本通过 `switch_backdrop` 或背景切换事件引用它，删除确认会列出脚本与代码行，源码由用户自行修改。未命中任何 click_enabled 角色的按下会作为一条 stage-click 发送，派发到该时刻激活的背景；背景可添加/删除舞台点击事件区域，角色不允许拥有该区域。按键事件使用 `key:<名称>`，名称限单个小写字母、数字或 space/up/any 等预设值，一次按键会按绑定顺序执行所有绑定该键的对象。自定义旧项目基类需继承产品基类才能参与舞台同步，系统不覆盖原文件。格式与协议见 src/VisualizedAgentCoding.Domain/Projects/stage-format.md。

### 已实现：项目数据、旋转碰撞与积木投影

- 项目数据保存在 `project.json` 的 `variables` / `lists` 中，运行时按一次运行初始化，结束不写回初始数据。变量支持 number/text/boolean，列表当前存储文本。
- “更多 → 管理变量…”打开项目级管理器；变量和列表名称必须唯一于各自类别，但允许变量与列表同名。
- 数据引用服务扫描字面量形式的变量/列表 API 调用；重命名时改写磁盘脚本和未保存编辑器内容，修改通过 `TextDocument.Replace` 的局部编辑完成并保留撤销栈；存在引用时删除被阻止。
- 运行时 API 当前为 `get_variable`、`set_variable`、`add_to_variable`、`list_append`、`list_remove`、`list_clear`、`list_length`、`list_get`、`list_set` 和 `list_values`。`change_variable` 是 `add_to_variable` 的兼容别名；`list_values` 返回快照，遍历不会观察或修改共享列表。
- 碰撞使用当前造型图片尺寸、`size` 和 `direction`。角色与克隆体参与碰撞；隐藏对象和已删除克隆体除外。`touching` 使用旋转矩形分离轴检测，边缘接触算碰撞；`touching_pointer` 判断点是否在旋转矩形内；`touching_edge` 使用旋转后包围边界。
- 桌面端收集所有造型的图片尺寸并通过运行请求传递给 Python；缺少元数据时回退对象尺寸或 48×48。
- 碰撞箱调试层与图片使用同一组舞台几何字段（`CanvasLeft`、`CanvasTop`、`SpriteWidth`、`SpriteHeight`、`Rotation`），独立置顶显示，不随角色图层被遮挡。
- Python Helper 新增 `python.blocks`：输入单个已去缩进的区域正文，返回只读积木节点树；支持 `start` 区域的移动、旋转、goto、滑行、等待、重复、计数循环、列表遍历、条件、变量和造型切换，未支持语句及注释保留为 raw/comment 节点。
- `BlockEditorView` 提供 Python/图形化切换、左侧分类和只读积木行；打开对象脚本、切换模式或源码变化时刷新。当前不支持拖拽、参数编辑和写回。

### 已实现：编辑器缩进输入与显式转换

编辑器以 4 列为新输入的缩进单位；现有代码只在用户主动转换或粘贴新内容时处理，不在加载和保存时全文格式化。

1. **新输入的 Tab：** 启用 AvaloniaEdit 的 `ConvertTabsToSpaces`，将 `IndentationSize` 设为 4。按 Tab 时插入空格并补齐到下一缩进位置，不把所有位置的 Tab 都简单替换为固定四个空格。
2. **现有文本保持不变：** 打开和保存文件不自动替换 Tab。标准粘贴单独覆盖 AvaloniaEdit 默认的全文 Tab 替换行为，只转换插入范围内字符串之外的代码行首 Tab；粘贴到现有多行字符串时保留 Tab，沿用文档换行风格。剪贴板读取期间文档或选区变化时拒绝应用过期结果。
3. **显式转换命令：** “更多”及编辑器菜单提供可撤销的“转换缩进为空格”，处理当前脚本全部可编辑区域。输入、粘贴和显式转换统一按编辑器的 4 列制表位展开；行首一个 Tab 转为四个空格，混合空格时补齐到下一四列边界。字符串、非行首 Tab、系统标题及已有纯空格缩进不修改。v2 隐藏包装仍由投影处理；完整 Python 文件的结构识别遵循 Python 本身的规则。
4. **保持识别容错：** 新输入使用空格不能替代现有的混合缩进识别恢复。外部文件和粘贴内容仍可能包含 Tab；语法诊断继续报告实际缩进问题，保存流程仍保留用户原文。
5. **验收：** 覆盖行首及非缩进边界位置按 Tab 的补齐、多行字符串和续行字符串保真、LF/CRLF、转换的撤销重做、标准粘贴单次撤销、多区域保存及重新加载。

### 已实现：诊断归属与隐藏恢复错误处理

沿用已实现的用户视图行列映射与点击定位。Helper 返回原生/恢复来源，以及缺少代码块的恢复错误关联行；`ObjectScriptDiagnostics` 仅在已确认的对象模板中过滤隐藏位置的恢复连带报错。用户定义缺少方法体时定位到可见定义，清空启动或初始化体时提示该区域至少需要一条语句。多个区域的独立错误继续展示，无法定位的原生/未知来源错误保留中性提示，不直接归因于系统代码。最终列表去重后统一驱动错误数量、表头、状态栏及悬浮提示。结构识别失败仍走完整源码只读恢复入口，不据此过滤诊断。恢复解析仍是尽力而为，不保证列出所有语法错误。

## 总体原则

- 领域模型、积木算法、Python 转换和 Avalonia UI 分离。
- Python AST 解析通过独立 CPython helper 进程完成，不让 Python 运行时进入 UI 层。
- 双向同步以语义结构为目标；无法表达的语句转为保留源码的 `opaque/code block`，不能静默丢失。
- 编辑来源、文档版本和变更事件必须可追踪，避免 Python 与积木之间循环更新。
- 项目工作区与应用源码仓库分离；项目根目录用 `project.json` 管理资源和版本信息。
- 核心库不依赖 Avalonia、Git、具体 Python 进程实现或智能体供应商。

### v1 兼容视图与共用保存行为

v1 兼容路径已完成文档/区间模型、识别、词法标记校验、系统包装保护、保存合并和原文切片视图。v1 隐藏系统包装及标记，保留原有缩进；v2 使用下节的多区域缩进投影。识别失败时显示只读完整源码供恢复；普通用户脚本与无标记旧对象脚本全文可编辑。打开、重新加载及程序性替换源码后复检版本并重建投影，用户编辑不重新猜测边界。

语义约定：角色/背景脚本的用户区域仅用于角色/背景成员和事件逻辑，例如成员属性、实例方法和事件处理方法；模块级变量、普通函数与独立类应放在普通用户脚本中，普通用户脚本不受此限制。隐藏系统包装不改变 Python 作用域，也不会把顶格函数自动转成实例方法。本次明确语义，不额外引入 AST 定义类型检查；缩进错误仍可修正和保存，专门的成员语义诊断后续实现。

v1 切片视图不逐行增减空格，不改写多行字符串。非空视图没有末尾换行时，合并层仅补充与原文件一致的分隔换行，让隐藏结束标记独占一行；重新加载后该换行作为用户区域原文显示。空视图不补充。保存及分析仍以完整源码为依据，用户视图不另行持久化。

- 磁盘上的对象/背景脚本始终保存完整 Python 源码，包含系统管理的导入、同名类声明、共同基类继承及区域标记；编辑过程中的用户语法错误允许原样保存，不承诺所有保存版本语法有效。
- 用户代码区域以外的包装和运行时接口由项目系统生成并保护，用户普通编辑只能修改用户区域。v1 空区域继续显示空白；新建 v2 的类定义区为空，启动区显示可编辑的 `pass`。
- 编辑器隐藏系统包装和标记。v1 只显示原文用户切片，v2 显示只读分区标题及去除包装缩进后的用户代码；底层文件保有完整类和事件方法结构。
- 静态分析优先使用未保存的完整编辑器源码；未来运行器使用经确认的完整源码。编辑器视图与完整源码保持位置映射，用于诊断、引用、选择、光标移动和保存编辑；LSP 与补全尚未实现。
- 对象选择器切换对象时，根据稳定对象 ID 保存当前文档并加载关联脚本；普通用户脚本使用用户脚本视图，系统入口 main.py 不进入用户编辑流程，不套用对象类的隐藏区域规则。
- 外部修改、对象/类重命名、模板版本升级或用户代码区域标记损坏时，必须提供冲突检测和可恢复策略，不能静默覆盖用户源码。

识别约定：v1 模板版本注释放在首行，用户区域开始/结束注释在目标类中各独占一行，缩进为四个空格；系统 `pass` 保证空用户区域的完整文件合法。识别首先检查真实注释 token，再剥离用户区域校验必要导入、类名、继承和系统占位。用户语法错误与系统结构状态分开，不能用全文 AST 成功与否直接决定结构状态。标记内的顶格代码也不影响区域归属，重新加载后仍可编辑、保存；区域识别不保证用户代码的角色成员语义，专门的作用域诊断尚待实现。

混合缩进或错误退格导致 tokenizer 提前停止时，可使用不改写原文的去缩进词法视图读取注释并映射回原文；依然通过词法引号状态排除字符串伪标记，原始标记缩进和系统包装仍需通过校验。此恢复只用于结构识别，用户代码中的 Tab/空格和诊断保持原样。

识别结果分为已确认、旧脚本未标记、结构损坏、版本不支持；完整原文始终保留。只有已确认状态提供 UTF-16 半开区域，标记行不属于用户内容。初次识别时，未闭合字符串导致结束标记无法可靠识别则返回结构问题，不用文本搜索强行修复。保存会话可复用此前已确认的边界；旧脚本迁移和模板升级仍属于后续工作。

保存实现位于 `Application/Editor/ObjectScripts/ObjectScriptSaveService` / `ObjectScriptSavePlan`。当前投影更新完整源码后复用全文合并入口，核对系统前缀及后缀，只替换用户区；另有接受用户区文本的计划入口，尚未直接用作界面保存入口。旧未标记脚本保持全文保存兼容；损坏模板不猜测边界，服务仅在全文修复稿重新通过结构识别后允许保存修复稿，当前只读恢复界面需在外部修复后重新加载。不支持版本的模板拒绝合并，不自动降级。

`MainViewModel.ScriptSaving.cs` 维护打开时原文、保存后已确认锚点和保存互斥；Helper 分析异步执行，应用前复检当前项目、脚本及文档版本。磁盘原文及索引变化时拒绝覆盖；无本地修改的导航/退出不写文件，保留外部更改。手动保存仍提示磁盘变化。当前采用乐观检查及单文件原子写入，不宣称跨进程原子比较交换。

手动保存、脚本/项目切换、关闭项目及退出自动保存复用同一异步保存流程；失败时保持当前缓冲区与窗口。用户通过编辑器右键请求重新加载后，确认框明确提供保留编辑或丢弃编辑并加载磁盘的选择；不会因冲突自动丢弃内容。自动保存策略仍由独立策略接口提供。

工具栏提供“重新加载”和“更多”入口，确保恢复操作不依赖编辑器右键路由；右键、Shift+F10 和“更多”共用菜单，键鼠事件在编辑器外层捕获，右键菜单在当前输入事件结束后弹出。

重命名计划携带对象脚本的未保存覆盖内容时也执行只读合并预检，并由 App 检查当前打开原文与磁盘是否一致；不会通过重命名绕过系统区域保存检查，也不会让预览提前保存缓冲区。

缓存、构建产物、解释器环境、临时输出和机器路径不得写入项目目录或项目历史；用户配置与 API 凭据存放在应用配置或凭据存储中。

### 多区域视图与包装缩进隐藏（核心、基础按钮与 v1 显式升级已实现）

本节描述完整目标，其中模型、模板协议、识别、保存、多区域投影和包装缩进转换已实现。`ProjectService` 新建角色/背景时调用 `CreateMultiRegion` 生成 v2；`MultiRegionProjection` 生成只读标题和用户切片，`PythonWrapperIndentation` 处理字符串之外的包装缩进，`MultiRegionReadOnlyProvider` 维护可编辑区动态锚点。诊断、引用及跳转通过 `IEditorProjection` 转换行列。保存使用可信区域快照生成计划，用户临时语法错误不导致保存时重新猜测边界；版本、清单和磁盘冲突检查保留。v1 继续使用原文切片视图，不自动迁移，也不增加用户脚本类型注释。协议细节见 `tools/python-helper/object-script-v2.md`。

标题及区域间分隔换行只读，用户区域内可输入、删除、粘贴及原生撤销重做；跨越只读边界的删除整体拒绝，不部分删除。选择和复制不受限制。标题末尾 Enter 在对应区域创建空行，首空行最左侧 Backspace 删除空行并返回标题末尾。用户写入同名中文注释不会改变区域身份。

#### 默认视图及代码语义

角色和背景脚本的新模板在用户视图中默认只提供两个分区标题；启动区域因属于方法体，显示可替换的 `pass`：

```python
# 类定义

# 程序启动时运行
pass  # 请删除此行并编写代码
```

类定义区允许为空，底层类已有系统管理结构保证合法。启动区保留可见的 `pass`，新增功能占位聚焦并选中所在整行；不采用空启动区对应隐藏 `pass` 的设计。这里“不隐藏占位”针对新增方法和事件体；现有 v1 类包装中的系统 `pass` 属于旧模板结构，迁移时单独处理，不能直接删除所有同名语句。

当前新生成的启动、初始化和事件占位为 `pass  # 请删除此行并编写代码`，提示属于可编辑、可删除的用户内容；不会追加到已有用户脚本。添加区域后会选中占位行；结构操作与普通输入共用撤销重做。诊断项点击会聚焦编辑器并选中错误位置的 token/符号；无用户视图位置的系统诊断只聚焦并提示来源，不选择无关代码。未闭合括号引起的末尾注释/EOF 恢复解析连带 `invalid syntax` 已过滤，独立代码行上的其他错误仍保留。深色主题错误项使用不同的 Fluent 悬浮填充和强调描边，避免默认与悬浮颜色相同。

| 区域                 | 用户代码的语义                                              | 完整文件中的归属                   | 包装缩进 |
| -------------------- | ----------------------------------------------------------- | ---------------------------------- | -------- |
| 类定义               | 类成员声明、自定义实例方法                                  | 角色或背景类内部                   | 一层     |
| 初始化（按需添加）   | `self.health = 100`、`self.items = []` 等实例状态初始化 | 约定的 `initialize(self)` 方法体 | 两层     |
| 程序启动时运行       | 对当前实例的方法调用、条件、循环等运行逻辑                  | 系统管理的启动方法体               | 两层     |
| 其他事件（按需添加） | 点击、按键、计时器、背景切换、消息等事件处理逻辑            | 对应系统事件方法体                 | 两层     |

类定义中的 `health = 100` 仍是 Python 类属性，不自动改写成实例属性；每个实例独立的变量在初始化区域使用 `self.xxx` 创建。模块级变量、普通函数和独立类放在普通用户脚本，普通用户脚本继续标准 Python 全文编辑。隐藏包装不改变作用域，不会把类体中的普通执行语句自动识别成启动逻辑。专门的成员语义诊断属于后续功能，不把用户作用域错误解释为区域丢失或锁死编辑器。

初始化是产品生命周期入口，不要求用户实现 `__init__` 或调用基类构造。系统管理的 `main.py` 通过产品运行时依次完成实例构造、运行环境注入、启动与消息处理器检查、每实例一次初始化，再开放同步消息路由并调用启动逻辑；停止后重新运行创建新实例。初始化失败中止剩余初始化及全部启动逻辑。克隆体、角色/背景点击、按键、计时器、背景切换、同步广播、动画、wait 和持续事件循环已接入。

#### 标题、区域身份及源码保真

- 中文标题由视图生成并保护，只读且可选择、复制。用户自行输入完全相同的注释时按普通用户注释处理，不创建、不切换区域。
- 每个区域有稳定 ID、类型、顺序和源码范围；事件区域另外记录事件身份或参数。以版本化系统标记或等价可靠结构恢复磁盘区域身份，不搜索中文标题，也不按生成的方法名认定事件身份。具体新标记协议需在实现前定义并增加协议测试。
- 完整源码仍为唯一保存和静态分析依据，投影不另存一份可独立修改的用户源码。系统导入、类声明、方法包装及区域标记隐藏并受到保护。
- 视图从第 1 列开始编辑，投影分别处理一层、两层包装缩进，保留用户自身嵌套缩进。不能逐行 `TrimStart`、全文替换 Tab 或盲目添加空格；多行字符串内容、注释、换行和未修改源片段必须保真。
- 未闭合字符串及其他临时语法错误允许继续编辑和保存；已确认边界不随每次用户输入重新猜测。不能可靠确定词法状态时保留原文并明确报告，不能为生成合法源码静默改写字符串。
- 单偏移映射扩展为带区域身份的双向范围映射：覆盖 UTF-16、行列、隐藏标题及包装、选择、补全预留、诊断、引用查询/跳转和新方法选区。系统代码中的结果提示来源，不跳到无关用户代码。
- 所有多区域修改及保存继续检查文档版本、当前项目/脚本身份、系统结构、清单和磁盘冲突；过期分析不得覆盖新内容。

#### “添加功能”按钮与可见占位

当前入口位于编辑器“更多 → 添加”原生悬浮二级菜单；右上角仅保留“更多”，重新加载磁盘文件和查找引用保留在菜单中。已接入自定义方法（名称校验、重名拒绝、角色方法补 self、普通脚本生成模块级函数、插入后选中 pass）、初始化方法（v2/v3 角色/背景限定，已有则定位，避免重复）、v3 消息事件，以及导入管理浮层（普通用户脚本和 v3 对象启用，旧对象先升级）。其他事件菜单尚未开放。

自定义方法插入使用编辑器原生文本撤销。新增初始化使用同一原生撤销栈：将文本修改与前后可信文档、区域 ID、只读锚点及有方向的选区恢复组成一个撤销组；普通输入、方法插入和初始化新增按实际操作顺序撤销重做。已有初始化只定位，不增加撤销记录。保存不清空历史，保存后撤销新增区域可移除已保存的隐藏包装，并继续按最新磁盘基线复检冲突；主动重新加载或切换文档会清空旧历史。引用查询使用同一源码快照映射错误提示与结果行列，隐藏区域的语法提示不在用户列表显示，但保留结果不完整状态；导航仍持有原始全文位置。后续其他结构命令需复用此机制，消息区域管理已提供，其他事件添加和无标记模板迁移尚未提供；已确认 v1/v2 支持显式升级到 v3。

| 菜单项         | 角色/背景脚本                                   | 普通用户脚本                          |
| -------------- | ----------------------------------------------- | ------------------------------------- |
| 自定义方法     | 启用，在类定义区插入实例方法，自动补入 `self` | 启用，插入模块级函数，不补入 `self` |
| 初始化         | 启用，最多一个；已有时置灰                      | 置灰且不可选                          |
| 程序启动时运行 | 默认存在，已有时置灰                            | 置灰且不可选                          |
| 其他事件       | 按事件类型与身份添加，防止不允许的重复          | 置灰且不可选                          |
| 导入脚本       | v3 启用，旧版先升级；实际导入为模块级           | 启用，受管理导入与原手写导入并存      |

“自定义方法”只负责插入用户可编辑的普通定义模板，不为每个方法另建隐藏包装或独立事件区域。例如新增 `walk(distance=10)`，在角色类定义视图中插入：

```python
def walk(self, distance=10):
    pass
```

插入后通过投影映射选区，滚动、聚焦编辑器，并选中 `pass` 所在整行（包括缩进及提示注释，不包含换行）。用户输入直接替换，也可以取消选中并保留它。初始化区域同样选中占位整行；不隐藏、不自动删除、不在清空后自动补回。删除后留下空方法体时正常报告语法错误，保留原文和可恢复编辑状态。自定义方法输入使用与项目管理一致的主窗口内遮罩浮层，支持校验、Enter 确认和 Escape 取消。初始化在视图中固定显示于类定义和启动代码之间，磁盘已有区域顺序和源码不自动改写；坐标映射按各区域稳定 ID 保持。

按钮修改作为一次可撤销操作，撤销/重做同时恢复源码、区域身份及选区；不得通过刷新整段文本破坏编辑器撤销记录。删除非空功能区域前确认；类定义与默认启动区的保留/移除规则在命令层明确，不能靠删除只读标题操作。用户直接修改自定义方法名称、参数或方法体仍应保留，不把按钮生成内容永久锁定为模板。

#### 已实现的导入规则与后续边界

角色、背景和普通用户脚本均可通过导入管理选择其他普通用户脚本；项目内角色、背景和自身导入被拒绝。已加入实际标准库目录及提供 broadcast 的公开运行时分类，内部运行时模块不能直接导入，第三方包尚待依赖管理。

脚本身份和类型依据 `project.json` 中的稳定脚本 ID、`Kind` 及规范化后的真实路径，不增加额外的用户脚本类型注释。实际实现需同时校验选择器、命令层和手写源码的解析结果；不能只靠筛选菜单实现禁止导入。标准库、产品运行时和第三方依赖是独立策略，不因项目脚本限制而一并拒绝。动态导入的识别范围与未来运行前检查需明确，不把静态分析称为安全隔离。

受管理导入统一保存在模块级区，编辑器只读摘要与真实语句分离。普通脚本的手写导入保留且校验目标；角色/背景的用户区手写导入为规则错误，可选择当前行转换。转换保留目标、名称、别名和注释，不删除同行其他语句；不支持的复合/多行导入需先拆分。移除或修改别名不自动改写调用。具体协议以 `tools/python-helper/object-script-v3.md` 为准。

## 依赖方向

```text
App ───────────────> Application ───────> Domain
  │                         │               ▲
  ├─ Blocks.Avalonia ──────┼─> Blocks.Core ┘
  ├─ Stage.Avalonia ───────┼─> Stage.Core
  └────────────────────────┼─> Blocks.Runtime
                            └─> Ports <──── Infrastructure
Python helper <──────────── Python bridge
```

- `Domain`、`Blocks.Core`、`Stage.Core` 不引用 Avalonia 和具体外部服务。
- `Application` 只依赖领域模型和端口；它负责同步状态、取消、错误映射和用例编排。
- `Infrastructure` 实现端口，处理文件、Git、Python 子进程、安装包环境和环境检测；安装包内置环境不得写入项目目录或修改系统 PATH。
- Avalonia 项目只负责绑定、导航、输入和绘制；不得在 code-behind 中实现 Git、AST 或 Python helper 协议。
- `Blocks.Runtime` 修改 `StageScene`，由舞台层读取并绘制；运行时不直接调用 Avalonia 绘图 API。

### 用户脚本重命名的当前分层

- `Application/Projects/ScriptRenameService` 使用共享 `ProjectSourceService` 收集编辑器覆盖源码，调用 `IPythonBridge.PlanModuleRenameAsync`，返回包含磁盘原文、编辑原文及修改后源码的计划；预览期间不写磁盘。
- `ScriptRenamePlan.cs` 单独定义计划及文档快照模型；`ScriptRenameRules` 集中文件目标、脚本类型、主脚本保护和重名校验。模块名格式由应用层预检，Python 标识符、关键字及语义解析仍由 Helper 最终校验；创建脚本的文件名规则不等同于可导入的模块名规则。
- Helper 的 `python.planModuleRename` / `module_rename.py` 仅分析快照，按模块身份生成修改后源码。不全文替换名称，不修改函数名称；角色/背景重命名时只更新目标脚本的唯一类声明并校验新类名冲突，不执行用户代码；无法确认时返回问题并阻止应用。
- `MainViewModel.ScriptRename.cs` 管理重命名异步分析、独立取消、预览状态和确认；`ScriptRenamePreviewItem.cs` 负责行号等显示格式；`ScriptRenameView` 显示路径及修改前后源码。`MainViewModel.ScriptManagement.cs` 仅保留重命名/删除共用的界面状态与刷新协调。预览时阻止工作区输入，返回修改名称时恢复输入焦点；预览导致的失焦不会取消整个流程。
- 确认应用前复检编辑器版本、项目实例、清单、脚本集合及磁盘源码。源码变化时拒绝覆盖；用户需重新预览。成功后保持稳定脚本 ID，更新项目路径、引用方源码和当前编辑器。
- 应用时写入更新源码，再调用内部 `CommitScriptFileRename` 提交文件路径及清单；`IProjectSession` 不再暴露只改路径的重命名方法，避免界面绕过引用检查。底层提交通过现有测试程序集的内部可见性单独测试。可捕获的写入错误尝试逆序恢复源码和清单。清理失败的新文件保留待删除记录，避免被重新收录；持续 I/O 故障需人工恢复，界面明确报错，不声称成功。跨文件断电/崩溃恢复尚未实现。
- 当前范围限于合法 Python 标识符的用户脚本名称；关键字、`__init__` 和仅大小写变化拒绝处理。反射、运行时构造模块名及任意动态执行不在完整语义保证范围内。

### 删除引用检查的当前分层

- `Application/Python/ProjectSourceService` 通过 `IProjectStore` 收集项目源码，排除待清理脚本，应用未保存编辑器覆盖内容；空编辑器内容也优先于磁盘。
- `Application/Python/ProjectReferenceService` 处理光标符号查询；`Application/Projects/ScriptDeletionImpactService` 负责删除前置分析、失败和完整性归类、结果版本失效判断。两者共用源码收集能力，不持久化反向引用索引。
- `IPythonBridge.FindReferencesAsync` 和 `FindModuleDependenciesAsync` 使用独立请求契约；模块依赖查询不需要光标位置。Infrastructure 共用临时快照、进程通信、超时和 URI 映射，不包含删除决策。
- Helper 分别通过 `python.findReferences`、`python.findModuleDependencies` 提供符号和模块查询；`analysis_environment.py` 统一配置静态分析环境，不执行用户源码。
- `App/Composition` 提供默认分析存储适配器，ViewModel 支持注入 `IProjectStore`。`MainViewModel.ScriptDeletion.cs` 仅管理确认框、输入、显示文本和导航；删除检查拥有独立取消源和任务集合，关闭时取消并等待回收，不复用符号引用任务集合。
- 分析期间禁止确认；结果为完整、不完整、失败或过期。发现引用或结果未知时，用户可选择“仍然删除”。点击引用关闭确认框并定位，再次删除会重新查询。
- 结果展示导入依赖及其静态可解析的使用位置（包括多次别名调用），每条匹配导入语句列出一项；计数为引用位置数，包含导入，不等同于调用次数。不保证穷尽动态导入；语法错误或检测到动态导入时提示人工核对。不自动修改或删除引用方脚本。
- 测试按源码收集/符号查询、删除影响用例、桥接集成、ViewModel 交互分别组织；目前仍共用现有 .NET 测试项目，后续按规模拆分程序集。

## 关键约束

- 使用 self-contained .NET；每个平台提供外部环境版和内置环境版两种安装包。安装时探测 Python/Git 并在缺失时引导用户从官方来源安装；启动时必须复检，任一依赖不可用或不兼容时阻止进入工作区。
- Python helper 不继承不必要的宿主权限；用户代码执行与 AST 解析进程均可取消、超时并报告退出原因。
- Python 语法错误时保留原始源码和编辑状态，不清空积木；无法表达的语句必须保留为 opaque/code block。
- Python 不直接调用宿主 .NET API；用户代码执行必须位于受限子进程并可取消。
- 舞台保持 480×360、4:3 逻辑坐标；当前由 WorkspaceView 的 Viewbox/Canvas 绘制和处理静态拖动，后续按需拆分 StageControl/StageRenderer，不将目标目录视为已实现。
- C++ 不作为首版目录的一部分，只有性能测量确认后才增加独立原生库和窄 C ABI。
